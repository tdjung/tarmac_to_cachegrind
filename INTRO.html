01 / OVERVIEW
TARMAC LOGS → CACHEGRIND

Tarmac log를 cachegrind format으로 변경하여
code coverage를 확인하세요.

Convert Tarmac logs to Cachegrind format
to inspect code coverage.

지원되는 Tarmac log 형식은 다음과 같습니다.

The following Tarmac log formats are supported.

ES · Tarmac Text Rev 3t
Tarmac Text Rev 3t
 7095 tic ES EXC [1] Reset
                R MSP 20020000
 7097 tic ES (000226f8:f2400000) T thrd: MOVW r0,#0
                R R0 00000000
IT · ps
23676374100 ps E Run
23676380700 ps R r14 ffffffff
23676405900 ps IT (00024812:00000000) 00024812 494e T16 LDR r1,[pc,#312]

Cachegrind format은 파일·함수·소스 라인별 이벤트 카운트를 기록하는 텍스트 프로파일 형식입니다.

Cachegrind format is a text profile format that records event counts by file, function and source line.

Valgrind · Cachegrind documentation ↗

Cachegrind format의 파일은 내부적으로 개발한 Performance Profiler로 확인하길 권장합니다.

We recommend opening Cachegrind profiles with the internally developed Performance Profiler.

Linux에서 바로 사용 가능한 Performance Profiler tool은 GitHub에서 함께 제공됩니다.

The Linux-ready Performance Profiler tool is also available on GitHub.

02 / CONVERT

Python Script로 log 파일을 변환하세요.

Convert logs using the Python script.

Python 3.6.8+ELFARM OBJDUMP
Linux · shell
python3 tarmac_to_cachegrind.py /work/tests \
  --elf /work/cm4.elf --log-name tarmac_cm4.log \
  --objdump arm-none-eabi-objdump \
  --workers 4 --progress-stream stdout \
  -o /work/coverage
Linux · shell
python3 tarmac_to_cachegrind.py tarmac_cm4.log \
  --elf cm4.elf --objdump arm-none-eabi-objdump \
  -o cm4_cachegrind.out

아래 Bash 스크립트는 ud python3 tarmac_to_cachegrind.py ...로 실행하며, Python 옵션을 그대로 전달합니다.

The Bash wrapper runs ud python3 tarmac_to_cachegrind.py ... and forwards all Python arguments.

스크립트 두 개를 같은 폴더에 두고, ud를 사용할 수 있는 내부망 환경에서 실행하세요.

Keep both scripts in the same folder and run in your internal environment where ud is available.

run_compute_farm.sh ↓

Linux · shell
bash run_compute_farm.sh /work/tests \
  --elf /work/cm4.elf --log-name tarmac_cm4.log \
  --objdump arm-none-eabi-objdump \
  --workers 4 --progress-stream stdout \
  -o /work/coverage

Debug 정보를 읽기 위해 대상 펌웨어와 일치하는 ELF 파일이 필요합니다. objdump는 ELF 파일 정보를 읽기 위해 활용됩니다.

An ELF matching the target firmware is required to read debug information. objdump reads information from the ELF.

기본 탐색은 입력 폴더와 한 단계 아래까지입니다. 더 깊게 찾으려면 --max-depth 2를 추가하세요. 두 코어의 ELF가 다르면 --log-name으로 구분해 각각 실행하세요.

The default search covers the input folder and one level below it. Add --max-depth 2 to search deeper. For cores with different ELFs, run separately using --log-name.

addr2line은 자동 탐색합니다. 찾지 못하면 objdump -l로 소스 위치를 읽습니다.

addr2line is auto-detected. If unavailable, source locations are read using objdump -l.

내부망에서는 Multi-Processing (--workers)을 위해 Compute Farm 접근이 필요합니다.

In the internal network, Compute Farm access is required for multiprocessing (--workers).

폴더 일괄 변환에서는 각 파일 변환과 함께 전체 결과를 합산한 merge 파일과 추가 정보를 위한 JSON 파일이 생성됩니다.

Batch conversion generates individual profiles, a merged result, and JSON files with additional information.

03 / SELECT & MERGE

선택한 테스트 결과를 합산하세요.

Merge selected test results.

필요한 파일 또는 폴더를 selected.txt에 한 줄씩 적으세요.

List the files or folders to include in selected.txt, one path per line.

Linux · shell
/work/coverage
Linux · shell
/work/coverage/17_case017_tarmac_cm4_cachegrind.out

Left: selected.txt · Right: excluded.txt

Linux · shell
python3 tarmac_to_cachegrind.py \
  --merge-list selected.txt \
  --merge-pattern '*_tarmac_cm4_cachegrind.out' \
  --exclude-list excluded.txt \
  -o /work/coverage/selected_cm4_cachegrind.out

로그를 다시 파싱하지 않습니다. 기존 개별 출력 파일을 읽어 합산합니다.

This reads and merges existing individual profiles without re-parsing the logs.

폴더는 바로 아래 파일만 선택합니다. 상대 경로는 목록 파일의 위치 기준입니다.

Folders select immediate files only. Relative paths are based on the list file location.

같은 ELF로 생성된 개별 Ir 출력만 사용하세요. 이미 합산된 total은 입력으로 사용할 수 없습니다.

Use individual Ir profiles generated from the same ELF. Merged totals cannot be used as inputs.

파일명 17_case017_...의 번호 17은 결과의 Covered/Uncovered에서도 17로 표시됩니다. 번호가 겹치거나 없으면 --reindex로 새 번호를 부여합니다.

The prefix 17 in 17_case017_... remains test ID 17 in Covered/Uncovered. Use --reindex to assign new IDs when prefixes are missing or duplicated.

selected.txt는 필수입니다. 전체 중 일부만 제외하려면 결과 폴더 한 줄을 적고 excluded.txt에 제외할 파일을 나열하세요. 제외할 파일이 없으면 --exclude-list를 생략합니다.

selected.txt is required. To exclude a few files from a full folder, list that folder once and put exclusions in excluded.txt. Omit --exclude-list when there are no exclusions.

04 / READ THE RESULTS

Performance Profiler로 결과를 열고, Code Coverage를 추적하세요.

Open results in Performance Profiler and inspect code coverage.

다음 명령어로 Performance Profiler를 실행하세요.

Launch Performance Profiler with the following command.

Linux · shell
linux-unpacked/./performance_profiler total_merge_tarmac_cm4_cachegrind.out

  • ELF path와 arm-none-eabi-objdump path를 추가해주세요.
  • Set the ELF path and arm-none-eabi-objdump path.
  • Path mappings는 ELF 파일에서 읽은 경로와 실제 source 위치가 다르다면 설정해주세요.
  • Configure Path mappings if paths recorded in the ELF differ from the actual source locations.
  • Code Coverage를 위해 합산한 결과와 정보이므로 Overview의 Performance Events와 Metrics 정보는 활용하지 마세요.
  • These results and data are aggregated for Code Coverage. Do not use the Performance Events or Metrics information in Overview.
  • 아래쪽의 Code Coverage Summary를 확인해주세요.
  • Check the Code Coverage Summary below.
  • Sources 혹은 Functions를 선택하면 오른쪽 탭 위쪽에 source code, 아래쪽에 assembly code가 표시됩니다.
  • Select Sources or Functions to see source code above assembly code in the right pane.
  • 각 line을 클릭하면 source code와 매칭되는 assembly가 파란색으로 표시됩니다.
  • Click a line to highlight the matching assembly in blue.
  • 초록색은 실행된 line, 빨간색은 실행되지 않은 line, 회색은 compile에 포함되지 않은 line입니다.
  • Green indicates executed lines, red indicates unexecuted lines, and gray indicates lines not included in compilation.
  • 각 line의 Ir 값은 merge에 포함된 모든 log의 합산 결과입니다.
  • Each line’s Ir value is the sum across all logs included in the merge.
  • 오른쪽 위 Events에서 추가 정보를 확인할 수 있습니다.
  • Select Events at the top right for additional information.
Event의미Meaning
Tests

해당 line을 커버한 테스트 개수

Number of tests covering the line

Covered1–5

커버한 테스트 번호를 최대 5개 표시합니다. 5개 미만이면 남는 칸은 0입니다.

Up to five covering test IDs; unused slots are 0.

CoveredSet

5개를 넘으면 나머지 테스트 번호 집합을 가리키는 번호입니다. coverage_index_tarmac_cm4.json의 sets에서 확인합니다. 나머지가 없으면 0입니다.

A set ID for the remaining covering tests beyond the first five. Look it up under sets in coverage_index_tarmac_cm4.json; 0 means no remainder.

Uncovered1–5

커버하지 않은 테스트 번호를 최대 5개 표시합니다. 남는 칸은 0입니다.

Up to five non-covering test IDs; unused slots are 0.

UncoveredSet

커버하지 않은 테스트가 5개를 넘으면 나머지 집합 번호를 표시합니다. 같은 JSON에서 확인하며, 나머지가 없으면 0입니다.

A set ID for remaining non-covering tests beyond the first five, in the same JSON; 0 means no remainder.

선택 merge의 인덱스 파일은 출력파일명.coverage_index.json입니다. 테스트 번호의 입력 경로는 tests에서 확인하세요.

For selective merges, the index filename is output-filename.coverage_index.json. Look up input paths under tests.

추가 이벤트는 소스 라인별 대표 실행 PC에만 기록됩니다. Assembly에서는 Ir만 참조하세요. Ir=0인 PC의 추가 이벤트는 모두 0이며, 완전히 미실행된 라인도 Covered/Uncovered가 0입니다.

Extra events are stored on one executed PC per source line. In assembly, refer only to Ir. All extra events are zero for PCs with Ir=0, including Covered/Uncovered on entirely unexecuted lines.
