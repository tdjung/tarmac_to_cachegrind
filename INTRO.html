두 가지 Arm Tarmac 형식을 PC·소스 라인별 실행 횟수로 변환합니다. 여러 테스트를 합치고, 어떤 테스트가 코드를 실행했는지 확인하세요.

Turn two Arm Tarmac dialects into execution counts by PC and source line. Combine tests and identify which ones exercised your code.

01 / CONVERT

한 파일로 시작하세요.

Start with one script.

대상 펌웨어와 일치하는 ELF가 필요합니다. 두 코어의 ELF가 다르면 로그 이름으로 구분해 각각 실행하세요.

Use the ELF that matches your firmware. If the two cores use different ELFs, select each core's log name and run separately.

tarmac_to_cachegrind.py디버그 정보가 있는 ELFELF with debug informationArm objdump / addr2line
Linux · shell
python3 tarmac_to_cachegrind.py /work/tests \
  --elf /work/cm4.elf --log-name tarmac_cm4.log \
  --objdump arm-none-eabi-objdump \
  --workers 4 --progress-stream stdout \
  -o /work/coverage

기본 탐색은 입력 폴더와 한 단계 아래까지입니다. 더 깊게 찾으려면 --max-depth 2를 추가하세요. Worker 수는 서버의 실제 CPU 할당량에 맞추세요.

The default search covers the root and one directory level below it. Add --max-depth 2 to go deeper. Set workers to match your actual CPU allocation.

Linux · shell
python3 tarmac_to_cachegrind.py tarmac_cm4.log \
  --elf cm4.elf --objdump arm-none-eabi-objdump \
  -o cm4_cachegrind.out

ELF의 미실행 명령어도 Ir=0으로 남습니다. 출력 폴더는 미리 생성하세요.

Unexecuted ELF instructions remain in the profile with Ir=0. Create the output directory beforehand.

addr2line은 자동 탐색합니다. 찾지 못하면 objdump -l로 소스 위치를 읽습니다. Ir은 실행 횟수이며 시간이나 캐시 hit/miss가 아닙니다.

addr2line is auto-detected; if unavailable, source locations come from objdump -l. Ir counts executed instructions, not time or cache hits/misses.

02 / SELECT & MERGE

필요한 테스트만 다시 합산.

Merge just the tests you need.

로그를 다시 파싱하지 않습니다. 기존 개별 출력의 파일 또는 폴더 경로를 한 줄씩 적고, 제외할 파일을 별도 목록에 넣으세요.

No trace re-parsing. List existing individual profile files or folders, one path per line, and put exclusions in a separate list.

selected.txt
/work/coverage
excluded.txt
/work/coverage/17_case017_tarmac_cm4_cachegrind.out
Linux · shell
python3 tarmac_to_cachegrind.py \
  --merge-list selected.txt \
  --merge-pattern '*_tarmac_cm4_cachegrind.out' \
  --exclude-list excluded.txt \
  -o /work/coverage/selected_cm4_cachegrind.out

폴더는 바로 아래 파일만 선택합니다. 상대 경로는 목록 파일의 위치 기준입니다. 제외할 파일이 없으면 --exclude-list를 빼세요.

Folders select immediate files only. Relative paths are based on the list file's location. Omit --exclude-list if nothing needs excluding.

같은 ELF의 개별 Ir 출력만 사용하세요. 테스트 번호는 유지됩니다. 번호가 겹치거나 없는 파일은 --reindex로 새 번호를 부여할 수 있습니다.

Use individual Ir profiles from the same ELF, not merged totals. Test IDs are preserved; use --reindex for missing or colliding IDs.

03 / READ THE RESULTS

Total을 열고, 테스트를 추적하세요.

Open the total. Trace the tests.

01 · PROFILE

합산 프로파일

Merged profile

PC·라인별 실행 횟수와 테스트 커버 정보입니다. 개별 파일은 1_case001_tarmac_cm4_cachegrind.out처럼 저장됩니다.

Execution counts and test coverage by PC and line. Individual files use names such as 1_case001_tarmac_cm4_cachegrind.out.

total_merge_tarmac_cm4_cachegrind.out
02 · INDEX

테스트 번호 목록

Test index

테스트 번호의 원본 경로와 CoveredSet·UncoveredSet의 나머지 목록을 찾습니다.

Look up original paths and the remaining test IDs referenced by CoveredSet and UncoveredSet.

coverage_index_tarmac_cm4.json
03 · REPORT

처리 결과

Processing report

성공·실패와 처리 시간을 확인합니다. 변환에 실패한 테스트는 미커버로 집계하지 않습니다.

Check successes, failures and processing times. Failed conversions are not counted as uncovered tests.

batch_report_tarmac_cm4.json

위 이름은 폴더 변환 기준입니다. 선택 merge는 지정한 출력명 뒤에 .coverage_index.json, .merge_report.json을 붙입니다. Total과 목록은 함께 보관하세요.

These names apply to batch conversion. Selective merging appends .coverage_index.json and .merge_report.json to your output filename. Keep the total and its index together.

Source code

Ir: 실행 횟수 · Tests: 커버한 테스트 수.
Covered1~5 / Uncovered1~5: 테스트 번호. 나머지는 Set 번호로 목록에서 확인합니다.

Ir: execution count · Tests: covering test count.
Covered1~5 / Uncovered1~5: test IDs. Look up overflow lists using the Set ID.

Assembly

Ir만 참조하세요. 다른 이벤트는 라인 정보를 대표 PC 한 곳에 저장한 값입니다. 미실행 라인의 추가 이벤트는 모두 0입니다.

Read Ir only. Other events store source-line metadata on one representative PC. Extra events are all zero for unexecuted lines.
